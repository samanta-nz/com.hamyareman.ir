## ۳) ریشهٔ مشکل آروان

باکت `hamyar-e-man` **هر نوع نوشتنی را رد می‌کند**، در حالی که خواندن سالم است.
زنجیرهٔ شواهد:

| آزمون | نتیجه |
|---|---|
| `ListBuckets` با همان کلیدها | ✅ موفق |
| `HeadBucket` و `ListObjects` روی `hamyar-e-man` | ✅ موفق |
| `PutObject` یک‌بایتی، بدون هیچ هدر اضافه | ❌ `InvalidArgument` / HTTP 400 با **پیام خالی** |
| PUT دستی‌امضاشده (path-style و virtual-host) | ❌ همان خطا |
| اثر تنظیم چک‌سام botocore (`when_required`) | بی‌تأثیر — هر دو حالت رد می‌شوند |
| ساخت باکت تازه در همان حساب + نوشتن در آن | ✅ **موفق** |
| روشن‌کردن نسخه‌بندی روی باکت تازه + نوشتن | ✅ موفق — پس نسخه‌بندی مقصر نیست |
| `GetBucketLocation` | `ir-thr-at1` — endpoint درست است |
| حجم باکت | ۲۷۵ شیء / ۰٫۴۱ GB (با نسخه‌های قدیمی ۰٫۵۳ GB) |
| بازنویسی یک شیء موجود با همان بایت‌ها | ❌ همان خطا |

**نتیجه:** نه کلید خراب است، نه کد، نه منطقه، نه نسخه‌بندی، نه سهمیهٔ حجم.
حساب آروان سالم است و باکت تازه می‌پذیرد؛ فقط خودِ باکت `hamyar-e-man` سمت
ArvanCloud در حالت «فقط‌خواندنی» است. این با شکست پیوستهٔ `sync-arvan` در
اجراهای زمان‌بندی‌شدهٔ اخیر هم می‌خواند.

برای پیگیری با پشتیبانی آروان، یک شناسهٔ درخواست نمونه:
`tx0000021c070df3b636360-006abc6e0a-3164252725-ir-thr-at1`

گزارش خام: `ci-report/arvan-diagnose.md`.

## ۵) قدم بعدی

آپدیت اجباری هنوز روشن نشده است. سه راه پیش رو:

1. **رفع در پنل آروان** — وضعیت باکت `hamyar-e-man` بررسی/آزاد شود، سپس
   ورک‌فلوی انتشار دوباره اجرا می‌شود و همه‌چیز خودکار تمام می‌شود.
2. **باکت تازه فقط برای APK** — چون `internalUrl` از سرور می‌آید و در APK
   کامپایل نشده، نسخه‌های نصب‌شدهٔ فعلی هم بدون تغییر کد از باکت تازه دانلود
   می‌کنند. محتوای درسی روی باکت قدیمی می‌ماند (خواندنش سالم است).
3. **فقط سرور خارجی** — توصیه نمی‌شود: آپدیت **اجباری** با تنها لینک گیت‌هاب،
   کاربران داخل ایران را زمین‌گیر می‌کند.
